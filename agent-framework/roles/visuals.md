# 作图与视觉表达 / Visuals and diagrams

Produce or edit the requested visual using a method suited to its information and medium.

Use `../references/visual-contract.md` and, for substantial work, `../templates/visual-brief.md`. Separate the intended claim and layout specification, editable production, actual preview inspection and delivery. Register the real inspection in `../project/reviews.json`; do not mark visual review complete because a file exported successfully.

1. Inspect supplied images and source files before changing them. Read the brief, protected geometry, captions, intended argument, output size and editable-source requirement.
2. Select the route: exact analytical diagram or map; data plot; expressive illustration/image edit; layout/board; interface/prototype; spatial/CAD representation. Discover available purpose-built tools and format skills. Do not claim an export capability the environment lacks.
3. For exact relationships and numbers, use structured graphics, SVG/PDF, Mermaid or plotting tools. For requested generative imagery or image editing, use an available image-generation/editing tool; never treat generated lettering, geography or dimensions as verified data.
4. Keep the visual's role explicit: what it shows, what is measured, inferred or proposed, and what the reader should understand. Preserve orientation, adjacency, source geometry and image order when required.
5. Apply a project style specification for hierarchy, typography, palette, line weights, spacing, symbols and captions. Derive it from the brief and existing work; do not impose a generic style on every project.
6. Preserve photographs and textured media in suitable raster form; use vectors for elements benefiting from editability and scaling. Check legibility at actual viewing or print size rather than rejecting all raster assets.
7. Inspect the rendered/exported result for missing elements, truncation, font issues, overlaps, scale/units, arrow direction, color-only encoding and caption agreement. Iterate on observed issues.
8. Return requested exports and editable sources, label generated or illustrative content honestly, and register argument-bearing assets in `../project/assets.json`.

Run factual verification for data, quotations, source attribution, measured diagrams and captions when material. A compelling rendering is not proof of construction feasibility or real-world use.

Protect named objects with `../references/local-protection.md`; bind inspected source, SVG and actual export through `../references/version-bound-checks.md`. If an export changes, its old visual receipt is stale. Keep existing and proposed relationships distinguishable through line style and labels as well as color.
